A-06 — @Preview coverage

⚠ Partial

Every UI state (loading, empty, error, success) must have a @Preview. Auth and Chat are exemplary. Profile is missing uploading and error previews. Dashboard has none.

AuthScreen.kt ✓ Pass
4 previews: sign-in, sign-up, loading, error. Full state coverage.
ChatScreen.kt ✓ Pass
9 previews: empty, with messages, loading, with input, message bubbles (user + assistant + streaming), typing indicator, input bar (empty + with text). Excellent coverage.
ProfileScreen.kt ⚠ Partial
1 preview (default loaded state only). Missing: isUploadingAvatar = true state, error != null state, and empty-name placeholder state. The ProfileState has all of these — they're just not previewed.
DashboardScreen.kt ✗ Fail
No previews. The screen is an empty Box(modifier = Modifier.fillMaxSize()) — a placeholder with no design intent.
SettingsScreen.kt ✓ Pass
1 preview. Acceptable — settings is static content with no meaningful state variation.
SplashScreen.kt ✓ Pass
1 preview. Acceptable — single-purpose animation screen with no state variation.

A-09 — Design tokens before components

⚠ Partial

No hardcoded Color() or fontSize values found anywhere — that's clean. However, hardcoded .dp literals are widespread in spacing and sizing across four files. The token system (BasilSpacing, BasilTokens) is well-built but underused.

Colours & Typography — all files ✓ Pass
Zero hardcoded Color() calls outside theme files. Zero hardcoded fontSize values. MaterialTheme.colorScheme and MaterialTheme.typography used throughout.
AuthScreen.kt ✗ Fail
11 hardcoded dp values: 48.dp, 36.dp, 10.dp, 4.dp, 22.dp, 6.dp, 14.dp, 8.dp. Most have direct BasilSpacing equivalents (xs=4, sm=8, lg=16, xl=24). The values not covered by BasilSpacing (10, 22, 28, 36) should become BasilTokens entries under an AuthScreen group.
ChatScreen.kt ✗ Fail
13 hardcoded dp values in message bubble sizing and layout: 280.dp max width, 16.dp/4.dp corner radii, 12.dp/8.dp padding, 6.dp dot size, elevation values. Chat bubble geometry should live in BasilTokens under a ChatBubble group.
ProfileScreen.kt ✗ Fail
AvatarSize = 96.dp (private val, not in BasilTokens). Icon sizes 20.dp and 14.dp not in tokens (BasilTokens has IconSizeMd=24 and IconSizeSm=16 but not 20 or 14). CircularProgressIndicator size=32.dp should use BasilTokens.IconSizeLg.
SplashScreen.kt ⚠ Partial
2 hardcoded dp values: 16.dp (use BasilSpacing.lg) and 6.dp (no BasilSpacing equivalent — add to tokens or use xs=4).
BasilLeaf.kt ⚠ Partial
Default parameter size: Dp = 28.dp and internal preview values (64.dp) are hardcoded. Preview-only values are acceptable; the default parameter should reference a token if BasilLeaf has a canonical size.

A-10 — Empty and error states

✗ Fail

Empty and error states must be rendered — not just present in the ViewModel. A state that exists in the data class but is never shown to the user is invisible.

AuthScreen.kt ✓ Pass
Error state rendered as a visible error banner below the submit button. Loading state disables the form.
ChatScreen.kt ✓ Pass
Dedicated ChatEmptyState composable shown when messages.isEmpty(). Error rendered as a Snackbar via LaunchedEffect(error). Loading shown as typing indicator dots.
ProfileScreen.kt ✗ Fail
ProfileState.error exists in the ViewModel and is set on avatar upload/remove failure — but it is never rendered. ProfileScreenContent receives the full ProfileState but there is no LaunchedEffect(state.error), no Snackbar, no error text. Avatar upload failures are silently swallowed.
DashboardScreen.kt ✗ Fail
The screen is Box(modifier = Modifier.fillMaxSize()). It has no ViewModel, no state, no empty state, and no error state. When a user taps the Home tab they see a blank screen with no explanation. Needs to be designed and built from scratch.
SettingsScreen.kt / SplashScreen.kt ✓ Pass
Static screens with no error or empty states required by design. N/A.

Critical
ProfileScreen.kt — wire error state to UI
ProfileState.error is set on avatar failure but never shown. Add a Snackbar or error banner in ProfileScreenContent matching the pattern in ChatScreen. Owner: Frontend Builder.
Critical
Replace all hardcoded .dp literals with BasilSpacing / BasilTokens
Affects AuthScreen (11 instances), ChatScreen (13 instances), ProfileScreen (6 instances), SplashScreen (2 instances). Add missing token groups to BasilTokens.kt: AuthScreen (padding 28, 36, 10, 22), ChatBubble (corner radii, max width, dot size), Profile (avatar size 96dp, small icon sizes). Owner: Frontend Builder.
High
Dashboard — design artefact required before any build work
DashboardScreen is an empty placeholder. Before it can be designed, a brief is needed. Once the PM scopes the Dashboard feature, design produces an artefact, and the Architect specifies the implementation. No code is written until there is an approved design.
High
Design artefacts for Check-in, Onboarding, Persistent Memory before Architect begins TDD
PM specs are approved. Design must produce wireframes/mockups for all three features before the Architect can write TDDs. This is the correct gate — not a gap in the current codebase, but must be completed before the build pipeline moves forward.
Medium
ProfileScreen.kt — add missing @Preview states
Add previews for: uploading avatar (isUploadingAvatar = true), error state (error = Res.string.error_avatar_upload_failed), and empty name (name = ""). Owner: Frontend Builder.
Low

Default size: Dp = 28.dp is hardcoded. If 28dp is the canonical leaf size for in-content use, add BasilTokens.LeafSizeMd = 28.dp. Minor — only if the leaf has a design-specified default.
